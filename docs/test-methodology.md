## 总原则（错误→制度化）

出现错误后要记的不是"这个 bug 怎么修"，而是**什么制度缺失让它漏过、
让定位变慢**——补制度，保证同类错误结构性不再犯。复盘四问：

1. **哪个特性/改动引入了这个错误面？它的隐含假设是什么**（如"agent
   名是 ASCII"）——引入时有没有补这个假设的边界测试？
   → 制度：特性落地必须显式盘点它打破的既有假设并补对应边界测试。
2. **定位用了正确的方法吗**？纯机制层 bug（git/文件/编码/状态机）必须
   用确定性复现（单测/小实验/装置），禁止用真实 LLM e2e 碰运气（不可控、
   慢、贵，只做最终确认）。
   → 制度：bug 先按"机制层 vs LLM 行为层"分类选复现手段；机制层 3 分钟
   内无复现即写最小实验，不靠长跑试错。
3. **失败现场保留了吗**？测试失败删 log = 测试白跑，只剩断言消息无法
   定位。
   → 制度：测试装置失败必须保留现场（目录+日志），成功才清理。
4. **改装置/用新 API 先验证了吗**？先查文档或写秒级最小实验确认 API
   语义，不写完整代码跑长测试试错（_outcome 时序两次实测失败后改用
   sys.exc_info——先做 0.1s 实验即可知）。

## 方法条目

### 1. git 写前 pull 是硬规则

测试写消息统一走 `tests/test_meeting_concurrency.py` 的 `write_msg`
helper（写前 pull + commit + push，与生产 `commit_new_files` 同构）——
多 work 交替写不 pull 必然 push rejected。新测试写消息一律用它。

### 2. 进程检测

`pgrep -f` 会匹配运行它的 bash 包装自身 → 用方括号技巧
（`ps aux | grep "[x]xx"`）或精确 PID。**杀 loop 必须连带杀其 pi 子进程**
（先 `ps --ppid` 收集子进程再一起杀；pi 命令行不含讨论路径，按路径 grep
会漏检）；清理后残留检查必须覆盖 pi 进程形态。

### 3. 失败三分类

设计漏洞（修设计+实现）/ 实现误判（撤回回正确实现）/
测试问题（修测试/装置）。在错误归因上堆补丁会越改越乱。

### 4. 装置对齐生产形状

setup_env 用生产 `gen_protocol`；消息产物用 `write_msg`——装置与生产
路径不一致会掩盖真实 bug 或制造假失败。

### 5. 测试运行/观察分离（tests/run_tests.sh）

层 1（默认）每次真跑 + tee tests/.cache/last.log，观察从文件读（0 秒）；
层 2（显式 --reuse）指纹未变 + 上次 OK 才跳过（有掩盖风险，默认关）；
最终回归/诊断必须 `--force` 真跑。

### 6. 参数形态矩阵覆盖（二维）

路径/名字类参数测试覆盖全部调用形态：
- 维度 1 写法：绝对 / ./相对 / 裸名
- 维度 2 **字符集：ASCII / 中文**——git quotepath 只转义非 ASCII
  （中文名拿到带引号路径 → list_my_messages 恒空 → is_first 恒真 →
  freezing 卡死，2026-09-09 e2e 实测；纯机制层 bug 本可用单测抓住，
  viewers 中文名是产品核心，不是 exotic case；单测先于 e2e 的原则见
  总原则 2）
- 删代码时检查相邻代码块是否被连带误删（上游实测教训：abs_dir 规范化
  被连带删除后静默潜伏 3 天）。

### 7. 测试不留 session（用户 2026-09-04 定）

pi 冒烟/连通性测试产生的 session 是垃圾——测试结束后清理自己产生的
session（含主 pi 侧 `~/.pi/agent/sessions/<编码目录>/`，不只讨论目录
pi-sessions）。注意与"失败保留现场"（总原则 3）的边界：失败现场在
bug 定位完成前保留；成功/定位完成的 session 随手清。

**清理验收机制（2026-09-09 建）**：靠记忆逐项检查必然漏（afk-e2e 引导
session 漏删即反例——两代项目重复犯）。测试/验证结束跑
`scripts/check-residue.sh`（残留检查器）：一条命令报告三类残留——
主 pi 侧近 24h 非白名单 session / loop+pi 进程 / mv-* 目录，
输出"干净"或残留清单。退出码 0=干净 1=有残留。

### 8. 测试与产品目录隔离 + 用例级 teardown

wrapper/spec/环境类测试在 scratch 项目目录跑（临时 git 仓库 + 临时
session），不污染真仓库；每个用例结束**立即删除自己的产物**
（setup→act→assert→teardown 闭环），再跑下一个——产物路径同名也无所谓
（已被释放），不靠 sleep 赌时间戳（反例实测 2026-09-09：两条 prepare
同秒写同一 mv-spec-* 目录互相叠写，因验证命令未做用例级清理）。

### 9. 失败保留现场（2026-09-09 定）

concurrency 等测试装置 finally 用 `sys.exc_info()[0] is not None` 检测
失败——保留目录 + fake-*.log 供调试，成功才 rmtree；失败路径不得
return（会吞正在传播的异常 → 假通过）。实测不可靠方案：`_outcome`
`.result.errors`（finally 时未填充，时序在测试方法之后）、addCleanup
检测（共享 result 下跨测试累积误判）——不要再用。

### 10. 外部契约按字段拼接，不按值形状猜（2026-09-10）

消费外部接口（env 变量/配置文件/session 事件）时，按其**定义字段**
取值拼接，不得按值的形状（含不含某字符）猜语义。反例：pi 契约是
`PI_PROVIDER`=provider + `PI_MODEL`=模型 id（id 本身可含 `/`，聚合类
provider 的命名空间 id 如 `deepseek/deepseek-v4-flash`）；旧代码用
"含 `/` 就视为完整 ref"的形状启发式 → provider 被丢掉 → pi 按
`provider/id` 解析到**同名的另一个 provider**——不报错、行为相似，
静默失真（2026-09-10 用户质询 model 是否跟随主 pi 时实测暴露；
不在场的单测从未覆盖含斜杠 id 形态）。制度：①拼接函数统一且幂等
（已带前缀不重复拼）；②契约字段的形态矩阵（纯 id / 含斜杠 id /
已带前缀 / 字段缺失）必须进单测——形状假设即未经测试的假设。

**本例的真实来源（移植偏差，2026-09-10 git 溯源）**：上游 bash 实现是
正确的总是拼接（`full_model="$provider/$model"`）；2026-09-09 移植进
python 时被"顺手改写"为含斜杠则不拼——**移植不是重写**：逐句对照、
每处变动都要能说出理由并补测，否则静默引入语义变更（本例潜伏 1 天，
因错 ref 仍解析到可用模型而无人发现）。

### 11. 断言强度与范围 ≤ 保证强度与范围（2026-09-10 e2e10 评审）

写下的每一句断言（代码注释/docstring/日志/文档/横幅），其**强度**与
**范围**不得超过代码能保证的强度与范围。三个维度、各需在**写时**校核：

| 维度 | 校核时机 | 反例（本轮） | 正解 |
|---|---|---|---|
| 强度 | 写时 | "携带**完整**上下文"（实际默认 budget 有损：丢弃 2146 条、省略 1071 处）；"统计取自**同一来源**"（实际还有构建返回值）；"[start] **已启动** N 个 loop"（未校验存活） | 强度降级到可实现的事实（"按预算裁剪+折叠"；"已拉起 N 个进程（存活未校验）"） |
| 范围 | 写时 | "**不依赖任何扩展**"（构建期成立，运行期上下文仍受环境扩展渲染期裁剪影响） | 限定作用域（"构建期不依赖…；运行期受…影响"） |
| 引用完整性 | 被引用物状态变化时 | 注释写"单一心智模型（curated 不保证…，**docstring 已声明**）"而 docstring 中并无该声明；改名后旧名引用残留 8 处 | 被引用物变化 → **同批**更新全部引用处（撤回传播：引用已撤回断言的文本同样要改） |

判据须可指认"位置 + 保证"，不用于文风评审；本体范围 = 制品文本
（讨论消息天然含试探与修正，不逐句约束）。

### 12. 改名/值域变更的完成判据 = 分区语义自检（2026-09-10 e2e10 评审）

改一个对外取值（模式名/枚举/default）时，完成判据不是"我觉得都改了"，
而是**一次 grep 能判**的分区自检：

- **现行描述区**（源码注释/docstring/CLI help/测试命名/README/AGENTS/
  design.md 正文）：旧名**必须为空**
- **允许保留区**（`docs/examples/` 存档、design.md 决策记录、git 历史、
  测试里的非法值反例、**面向用户的迁移提示文本**——错误信息里有意提及
  旧值以指引迁移，如"若是旧版产物请清理后重跑"）：**必须保留**（否则规则
  活不过第一次运行）

配套硬教训：**"值只存在于每次生成的产物里，无迁移负担"是错的**——值一旦
写盘就会存活（实测 `/tmp` 下 rename 前的 `protocol.json` 里
`"forkMode": "curated"` 仍在，重跑即命中静默走偏分支）。因此值域变更必须
同时加**解析入口守卫**（非法值就地报错，见方法 13）。

### 13. 配置值入口守卫：源头报错，不进重试路径（2026-09-10 e2e10 评审）

对外配置（`protocol.json` 的 `forkMode` 等）的合法值判定只在**实现处**
定义一次，并在**每个解析入口**设守卫；非法值就地失败，**不得**落到
"未匹配任何分支"的隐式路径。反例：`build_fork_source` 只对三个字面量
分支判断、无 else → 非法值静默走"边界后全量、不折叠、无预算"混合分支
（实测 6.13MB/930k tokens 超窗），且被 engine 的统一异常边界吞成
"每 2s 廉价重试"，600s 后以 `reason=stall` 收尾——**错误归因误导未来
读者**。守卫布点（四层，一次做完）：

| 层 | 动作 | 理由 |
|---|---|---|
| wrapper（bash） | **哑转发**余参，不解析值、不注入默认值 | 转发者只转发；默认值单一源在 python |
| CLI（argparse） | `choices` 引用常量 | 人输入早期反馈 |
| 常驻入口（`__main__`） | 非法 → `[fatal]` + 非零退出 | 配置错误不是运行期故障，不进 engine 重试路径 |
| 实现函数（fs 层） | 入口（I/O 之前）值域校验 | 值集合定义权在实现处；库调用者同样受守卫 |

测试要求：每层各一条（fs 层断言"报错且**目标文件未创建**"；入口层用
真实 subprocess 断言非零退出 + `[fatal]` + 无副作用；wrapper 层断言参数
**确实到达**下一层）。

### 14. 数字必须带（口径；测点），且判据要挂在提交动作上（2026-09-10 e2e10 评审）

写进文档/报告的数字，格式为**数字（口径；测点）**——"同处"是关键：
脚注、别节、口头都不算。反例（同一提交内）：`docs/design.md` §二 明文
要求"引用必须带唤醒序号""实测须附口径与测点"，而 §一 的规模表混用了
不同产物的条数/MB 与不同时刻的 tokens，且无锚。根因不是不知道规则，而是
**判据没有挂在提交动作上**（§二 是声明，不是检查点）。

三条配套约束：

1. **产物侧数字**（条数/MB/est）随源漂移 → 整节加统一锚
   （"产物侧，<日期>，主 session ≈N 条"）；**预算钉住值**（如 est）显式
   标注"不随源漂移"。
2. **消费侧数字**（tokens）必须带唤醒序号（w1/w5…），否则不可比。
3. **示意值须三约束**：标"示意"、指向权威口径、声明"不作验收口径"。

数字四分类（写之前先问"它属于哪类"）：配置派生（附推导式与重估触发）/
实测（附口径与测点）/外推（附依据与触发）/事后拟合关系（标注"事后归纳，
非原始设计目标"——不得用它追溯解释当初取值）。

**改数字前先判性质**：是**漂移**（同口径新测）还是**复测**（方法/装置
变化）？无锚旧值按**修订记录**处理——并列新值与旧值，并注明旧值口径
不可考（不得静默替换，否则读者无法判断口径是否已变）。

### 15. 触发条件必须指名一个现在就能用的观测点（2026-09-10 e2e11 评审）

任何带触发条件的记录（"当 X 超过阈值时再优化"）必须能回答：**现在用什么
命令/日志能观测到 X？** 观测手段不存在 = 触发条件不是判据而是修辞。反例：
记录写"观察 `status-*.json` / 日志即可估 RSS 与耗时"，而 `status-*.json`
只存 `sessionID`、`log()` 只打时间戳——该判据永久不可执行。修法二选一：
(a) 补一个**最小观测点**（如首唤日志加"构建 181ms/55MB"一行；不建指标
体系、不进 status）；(b) 把触发条件改写为可执行的复测流程（"插桩后复测
占比"），并标明它是**复测型**而非监控型。

### 16. 评审层表述纪律：观察句与机制句分级举证（2026-09-10 e2e11 评审）

讨论消息中的句子会流向制品（docstring / 决策记录 / 修复动机），因此**在
讨论中就要按制品的举证强度写**：

- **观察句**（"实测产物 body 3129 条，`c5d43076` 出现在 [0, 805]"）——
  必须可复现（注明命令/口径）；
- **机制句**（"副本是不可达的孤立节点"）+ **承载严重性/修复动机**的句子
  ——必须**推演过或引源码**，否则显式标注"推断"；机制句带**证据指针**
  （源码位置/探针命令）优于只写"推断"标记（标记会忘、指针仍在）。

本轮出现两例机制句失真（"孤立节点"、"parentId 指向区外"），均在被引用
进 docstring 前由交叉复核拦下——机制句的传播链上受同等强度约束。
同时：**引用已撤回的测量/方案时，不得并入成稿**（性能侧对已撤回"锚点
改写"的 0.07/0.27ms 测量即属此类）。

### 17. 修复顺序纪律：结构修复与其事实基础/声明文本同批（第三次应用）

多个修复若共享同一事实基础（同一计数器、同一不变量、同一动机句），必须
**同批落地**——否则验证时"先红后绿"的红色可能来自旧 bug，绿色可能来自
侥幸，观察对象失真。本轮实例：① `dropped` 计数重算必须与"comp 移除计数"
同批（否则 I5 台账断言被 stale binding 污染）；② 修复动机句必须基于
**修正后**的事实（"满足 I1、消除 last-wins 依赖"而非已被推翻的
"修复 replay 破坏"）；③ 声明文本（docstring/§一 表）与产物行为同批。

**反向断言（先红后绿）是 fixture 的存在条件**：新写的回归测试必须在
修复前的代码上**确实失败**（可用 `git show HEAD:<file>` 临时回退验证）。
只绿不红的测试无法证明它覆盖了该缺陷。

### 18. 批量文本替换必须验证生效（`str.replace` 静默失配）

**背景**：脚本化编辑用 `s.replace(old, new)` 时，若 `old` 不匹配（空白/换行/
前批次已改过该处），Python **不报错、静默无事发生**——"改动做了"是错觉，
而后续代码可能已经引用了"以为加上了"的名字。

**实测代价**（2026-09-11 同一会话两次，均由**真实调用路径**抓出）：
- ① 删除函数用索引切片 `s[i:j]`，`j` = "下一个锚点函数"位置——但两个小 helper
  恰在区间内 → `_dur`/`_hhmm` 被连带删除（NameError 暴露）；
- ② 加 import 的 `replace` 因前一批次已在同处加过一行而失配 → engine 调用了
  **未导入**的 `core_meeting_speak_count` → **真实 loop 在配额判断处崩溃**
  （fake agent 多进程测试抓到收敛失败；纯静态检查全绿）。

**方法**：
1. **每个替换后断言**：`assert old in s, old[:80]`——失配立即炸，不静默；
2. 多处编辑**优先字符串对替换，不用索引切片**（`s[i:j]` 的边界由别处代码决定，
   改动中间地带就会误伤）；
3. 删除函数区间用"下一个函数名"作终点前，先 `grep` 确认区间内没有别的定义；
4. 提交前跑**真实调用路径**：`python3 -c "import <mod>"`（抓未定义/未导入名）
   + 相关测试。两次失误都是真实路径抓到的——静态阅读与"看起来对"都不够。

### 19. 验证分层：测试挂在"代码改动"上，不挂在"发版"上（2026-09-11 发版冗余）

**背景**：发版时顺手跑全量测试（382 测试 / 5 分钟）看起来"更稳妥"，实为冗余
——发版动作本身只改 `package.json` 的版本号与文档文案，**零代码改动**；而区间
内的代码改动在其**实现提交时**已经跑过全量测试。

**判据**：「这段区间内有没有**未被验证**的代码改动？」——有则跑，没有则不跑。
不是「是否在发版」「是否要推送」「是否重要」。

**分层**：

| 时点 | 验证内容 |
|---|---|
| 实现提交 | **全量测试**（代码改了；这是唯一的测试时机） |
| 发版 | **打包验证**：`npm pack --dry-run` 核清单 + 真实安装后跑 CLI 冒烟 |
| 推送 | 无需测试（提交时已验）——只核 `git status` 干净 + 本地/远程一致 |

**例外**（唯一合理场景）：发版区间累积了多个提交、且距上次全量测试较久
（如跨天），此时补跑一次合理——因为"区间内改动已被验证"这个前提可能不成立。

**成本视角**：冗余测试不只是耗时——它稀释了"全绿"的信号价值（每次发版都全绿
时，人不再区分"这次真的验了代码"与"这次只 bump 了版本号"）。

### 20. LLM 测试的判据 = **时长**，不是"是否用 LLM"（2026-09-11 用户澄清）

**规则**（用户原话）：

> 我要求 llm 测试必须经过我同意的原因是 llm 测试会消耗大量时间，会影响我
> 后继的操作。因此如果能确保短时间结束的测试是没有关系的，比如仅仅测试
> 一下启动是没有问题的。

**判据**：

| 情形 | 是否需要事先同意 |
|---|---|
| 完整 e2e 讨论、多轮真实唤醒、分钟级以上占用 | **需要**（且用户在场） |
| 几秒内结束的链路验证（只验证启动、单次冒烟、构造即停） | 不需要 |
| spawn 了 pi/loop 但立即终止的测试 | 不需要，但要**主动报告**（说明起过、已停、有无真实请求发出） |

**配套纪律**：`mv.sh --start` 会 spawn loop → spawn pi（真实请求）——短测试
也要**想好怎么停**（构造完立即 cleanup + `check-residue` 复核）。

### 21. `mv.sh --start` 会真实启动分析（spawn loop + pi）——冒烟别用它

**背景**：`cmd_start` 做两件事：创建环境 + **启动 loop**。后者会立刻 spawn
`meeting_loop.py`，而 loop 首轮就 spawn `pi --mode json --print`——**真实 LLM
请求**。在 pi session 内跑（`PI_SESSION_ID`/`PI_SESSION_FILE` 都在）时没有任何
保护会阻止它。

**实测代价**（2026-09-11 两次，同一坑）：
- ① 验证"目录名构造"时跑 `mv.sh --start` → 真起了 2 个 loop + 2 个 pi 进程；
- ② 验证"目录可省略"时同样跑 `--start` → 同样起来（20 秒后 cleanup 删目录，
  loop 因 repo.git 消失自退出，但 pi 进程已 spawn → 请求可能已发出）。

**方法**：
1. **只创建不启动** → 用 python 侧 `start_discussion.py --dir <d> --spec <s>`
   （不带 `--start`）；wrapper 无此形态（`--start` 永远启动）。
2. 需要走 wrapper 链路时，验证完**立即**：停 loop（`pkill` 按目录精确匹配）
   → `--cleanup` → `check-residue.sh` 复核。
3. 判据："这次验证会不会 spawn pi/loop？"——会，就必须先想好怎么停。

### 22. 契约写成矩阵表：命令 × 形态 × 判别力（2026-09-11 e2e16 F5）

**背景（F5 回归）**：改 `cmd_view` 时只测"新形态"（目录可省略），
`--view <dir>` 的显式形态**改动前后都没有测试**（旧测试测的是"无参 → 报错"
的错误分支）；395 个测试全绿没挡住——真实多视角评审（e2e16）才抓出。

**诊断（不是"漏写一条用例"，是结构性缺口）**：
1. wrapper 测试按功能增量堆叠，没有"命令 × 形态"的系统性盘点；
2. **bash 层无行覆盖工具**——缺口不出现在覆盖率里（实测 Python 层 96%，
   wrapper 测不到一行）；`--wait` 零测试、`--cleanup` 省略形态零测试；
3. 旧测试用**弱断言**（仅 `assertNotEqual(rc, 0)`）——契约废除后静默变
   空洞：`test_view_requires_dir` 的"目录必传"契约已不存在，它只因测试
   cwd 里没有分析环境才继续绿，看起来在覆盖 `--view` 实则什么都没测。

**方法**：
1. **契约 = 一张表**（`tests/test_wrapper.py::TestCommandFormMatrix`）：
   每行一个形态单元格 = `(args, 前置条件, 期望 rc, 输出须含, 副作用)`。
   新增命令/形态必须补行——**结构性强制，不靠记忆**。
2. **每格三件事**：退出码 + **输出内容** + **副作用/文件效果**；
   禁止仅断言退出码（弱断言是僵尸测试的温床）。
3. **判别力优先于覆盖率**：显式参数格子必须能区分"用了显式值"与"恰好
   自动发现同一个"。做法：加**诱饵**（更晚时间戳 + 状态不同 `done` vs
   `stopped` + 独有标记）——两个同构环境的 HEAD/输出完全相同，无诱饵时
   F5 类 bug 照样绿（本次实测：加诱饵后重引入 F5，矩阵立即失败并报
   "走了自动发现（选到诱饵环境）"）。
4. **改写旧测试 ≠ 补充**：契约变更时先问"它测的是哪条既有契约、那条契约
   还有效吗"——有效则必须补等价用例；无效则删除并在表里补新形态格。
