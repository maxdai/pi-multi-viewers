## 一、结论（对主题的回答）

**摘要的帮助 = 装配与排版**：把散在会话里的事实集成一份**有界**概览（本场摘要 8,737 字符
≈ **2,912 est**，测点：`context-base.json.summary_est`）；**新事实 ≈ 0**——三方各自统计
"没有摘要就做不出的判断"均为 **0 条**（效率/0002 §六、简单/0002 §六、铁律/0003 §〇）；
效率的 106 实体五源探针中，最终"五源都查不到"仅 11%，逐条查看后全是正则碎片与排版
⇒ "独有"这一列被**整列删除**（效率/0007 §一）。

**代价（已量清）**：生成一次 **38s**（⚠ 反推，`context-base.json` 无墙钟字段；效率/0003 §一）＋
**$0.0138**（测点：`context-base.json.usage` = input 73,251 + output 4,726（含 reasoning 1,566），
合计 77,977 tokens）；携带成本 **`[未核实]`**（无 per-wake usage 记录，效率/0012 §四）；
以及一整套平行口径与一份按注释维持的复刻语义（见二·A3、三·2）。

**体量（决定性分母）**：用本仓确定性切分器 `iter_after_boundary`（字段判定，
`meeting_fs.py:417`）重算 agent 会话（测点：`pi-sessions/fork-src-14c6936c-….jsonl`，测量时点 249 条——该文件是 agent
的 live session，条目数随运行增长 ⇒ 数字绑定测点；效率/0019 §二）：
fork 携带的可见窗口 **26,962 est（17.4%）**、**本轮 agent 自产 128,158 est（82.6%）**、
锚点前死重 ≈1 est ⇒ 摘要（2,912）相对**整场 token 主项 < 2.5%**（效率/0019 §二）。
⇒ **真正的杠杆在工具使用纪律，不在窗口或摘要**。交接叙事仅 ≈118 est（可放下）。

**决策**：**默认 `budget` + `summary` opt-in——而这已经是现状**（零代码改动；
测点：`meeting_fs.DEFAULT_FORK_MODE='budget'`、`STARTUP_DEFAULTS['fork-mode']='budget'`；
效率/0010 §一）。**不删代码**，但保留路径的**准入条件 = 钉子**（见二·B）；删除代码登记为
**未采纳选项**（同效但风险更高，理由：同样拿到 38s/场的节省，删除单向往不可逆 + 迁移成本 +
失去再测量能力；效率/0010 §二）。

## 三、共同的纪律（本场沉淀，可直接复用）

1. **能拿掉的就别定规则**（六实例：`background.md` 的第二个写者、平行估算器 `window_est`、
   per-wake usage 的游标状态、替代节的必要性、第四口径字段、键名兼容行）。
2. **先找已登记的确定性事实／已经在手的线，再谈新建估算器或采集器**（实例：`iter_after_boundary`
   字段切分、`read_fork_stats` O(1) 读首行、缓冲 stdout 里的 usage）。
3. **任何比率/命中率断言必须声明"检查源 ∩ 被检对象 = ∅"**；**"字符串出现" ≠ "事实"**
   （实例：铁律把 `toolResult` 里的引用当成"上一代摘要"；效率首次算 40/40 自命中）。
4. **任何"占比/构成"类数字必须声明登记边界**或保守标注（`iter_after_boundary` 的旧账：
   子串判定致数字虚高 ≈4×）。
5. **改动量必须与被改对象的量级匹配**（为 <2.5% 的小数项改字段值 + 迁契约 + 迁消费者语义 ✗）。
6. **`n/a` 族**：写入端不伪造（缺失写 `n/a`，不填 0）＋ 聚合端不吞掉（`n/a` 按缺测，
   不进均值/中位）——适用对象含既有节律统计。
7. **发现偏差先做类型/字段级确认**：本场两次误判（铁律的 `toolResult`、效率的"字段名撒谎"）
   都源于用"看起来像"代替"是什么"。

## 六、未决 `[未决]` 与重估条件

**未决**
1. **帮助的用量**：三方自述合计 0 条硬需求；只能靠后续场次的被动读数积累。A/B 对照场被否
   （判据方差 > 效应量：效应 ≈半轮 ~70s，而唤醒本身 48–82s 波动 + 3 次瞬时故障尾部）。
2. **"只能来自摘要"的判定**与"指针通道不可区分"（任务书 / 仓库本身 / 摘要三源）——建议下一场
   刻意不给指针以区分。
3. **背景装配的生态事实**：同一份工作被两个子系统各做一遍（主会话里 MC historian 的
   **31 条**压缩摘要共 6,296 字符 ≈ 2,098 est，与我们 38s 的定向摘要同量级）；但 MC 那 31 条
   **从未进入**我们的 fork 源（实测 0 命中）⇒ 对**我们的背景**装配器是 **2 → 1**。
4. **瞬时故障**（生成超时 3 次，同输入复跑 56.2s 成功 ⇒ 归因瞬时）无法预防，只有 300s 超时 +
   可见回落 budget；缺事件流诊断。

**重估条件**
- **D-1**：之后**连续 3 场** `summary`（opt-in）**零使用** ⇒ 支持删代码（挂着不跑 ⇒ 漂移）。
- **D-2**：被动读数（单次检索读入 est 越界）出现 ⇒ 回滚或加护栏。
- **降级形态（若采 D-1）**：机器生成的**有界读数节**（**键=值格式**，上界由格式保证，
  内容只允许来自 artifact/`usage`，`--start` 时生成一次并冻结）+ 三条替代纪律
  （数字只回 artifact ／ 检索只带结论、不粘原文 ／ 任务书指针带测点）+ 与记账迁移**同批**，
  不留"无界窗口"中间态。

## 七、本场的元结论（对本项目自身）

1. **"票与现状重合"出现两次**：① 摘要器输入不携带上一代摘要（现状已正确，缺的只是写下来）；
   ② 默认 `budget` + summary opt-in（现状即结论）⇒ **边界常是"先把现状写下来"**。
2. **本场自身的 token 成本算不出来**（唤醒 28 次 / 跨度 924s = 15.4 分钟；`wake-logs/*.txt` 无 usage）
   ⇒ 这是 A4/A6 最强论据：不是整洁问题，是**让下一次同类决策有分母**。
3. **本场的实际最大支出是"核对我们自己的数字"**：按关键词段落统计，首轮约 **40–45%** 的发言量
   花在口径核对上（效率/0005 §二，宽口径估计，仅当量级看）。归因两半均可一行修掉：
   任务书事实底**无测点**（本场 `question.md` 的"已知事实"取自更早一次运行且未标测点，
   与本期 artifact 不符：覆盖 120/423/406,485 vs **126/489/451,043**——这条由 `简单/0001 §三·3`
   发现，铁律认账）+ 代码里平行度量未标单位。
4. **摘要的数字是负债不是资产**：本场摘要的 40 个数字中 **40/40 可在会话原文找到、
   0 个独有、仅 3/40（7.5%）可被本场记账核对**（效率/0008 §一）⇒ 正确率的上界 =
   可自核率；**用法只有一种：当路标，数字回 artifact**。本场已验证它会**原样复述陈旧数字**
   （`120`/`423`/`406,485` 在摘要里各 1 次，本场真值 0 次；铁律/0006 §〇）。
