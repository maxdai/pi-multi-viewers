## 二、逐条结论与依据

### F5【高】`--view` 显式目录被静默丢弃

- **位置**：`scripts/mv.sh:113-119`。shift 吃掉首参后**总是**走
  `resolve_dir ""`（自动发现），显式目录被丢弃。
- **性质**：相对改动前的**行为回退**（改前 `normalize_dir "$1"` 显式生效）；
  且是**静默**的——多 `mv-*` 并存或跨目录调用时会看错对象且无提示。
- **测试缺口（根因）**：`tests/test_wrapper.py:195` 仅有无参形态 `["--view"]`，
  显式目录零覆盖——测试全绿（395）没挡住的直接原因。
- **修复**（三方一致）：
  ```bash
  # 首参非空且非 --since → 显式目录；否则自动发现
  if [ -n "${1:-}" ] && [ "${1:-}" != "--since" ]; then
      dir="$(resolve_dir "$1")"; shift
  else
      dir="$(resolve_dir "")"
  fi
  ```
  与 `status/report/wait/cleanup` 的 `resolve_dir "${1:-}"` 同一判据；
  `--say` 保持"按参数个数"（文本可含空格/以 `--` 开头，**不能**按值判形）。
- **性能补证**（性能视角）：显式目录**反而省一次 find-dir spawn**——修 F5
  是恢复更快的路径，不是"加回功能付性能代价"。
- **验收**：补显式目录形态测试；这是"全绿没挡住"的教训，不只是修一行。

### F1/F2/F7 + 简单#2【高】降级兜底 = 一个概念，推荐整体删除

四类症状同一根因（"无 sid 匹配 → 取项目下最新 `mv-*`"的降级兜底）：

| 症状 | 后果 |
|---|---|
| **F1** 降级无机器判据（退出码仍 0，仅 stderr 文案） | `mv.sh --cleanup`（无参）**可删除不是本次分析的目录**；`--say` 可写错分析 |
| **F2** extension 靠 `err.includes("警告")` 还原布尔 | 文案一改，降级判断**静默**失效（同仓库内与"判据改退出码"的最新修正相矛盾） |
| **F7** `sorted(os.listdir)[-1]` 在降级路径比较整名（含 sid） | `mv-zzz-2025…` 排在 `mv-aaa-2026…` 后 → **系统性选旧目录**（与 docstring"取最新"不符） |
| 简单#2 | 同一概念的第四面 |

- **收敛（2:0:1）**：简单 + 铁律支持**删除**；性能中性（"不构成支持或反对理由"）。
- **删除依据（关键事实，经三方核查）**：**不存在"必须无目录且必然无 sid"的设计内
  场景**——pi 内两条通道都有 sid（bash 注入 / extension `ctx.sessionManager`）；
  终端主路径是 `--start` 输出的观看命令（本就显式带目录）；代码里兜底的原始动机是
  "PI 环境变量未注入时 wrapper 拿不到 sid"，属 pi 流程自身降级，不是给人用的便利。
  → 兜底不对任何设计流程构成负载。且**破坏性操作不应由工具猜目标**：
  最坏失败从"静默删错目录"变为"响亮报错要求显式目录"。
- **删除方案**：仅精确匹配 `mv-<sid>-*`（同 sid 时间戳可比 → F7 消失）；
  未匹配 → rc 1 报错，请调用方显式传目录 → F1/F2/简单#2 同时消失。
- **执行收尾三条**（简单视角提出，三方确认）：
  1. **`degraded` 概念删净**：`find_current_dir` 返回值收为一元（`path | None`）；
     `--find-dir` 退出码只留 0/1（**不留 rc 2 语义**）；extension 的
     `includes("警告")` 与 notify 警告分支一并删——不留无人消费的死代码。
  2. **错误文案留一处**：留 python 的（工具层贴近原因）；wrapper `resolve_dir`
     在 spawn 失败/rc=1 时透传 python stderr 后 `exit`，不另打一条。
  3. **测试变更**：删降级用例；加"无 sid 匹配 → rc 1"；**保留并新增显式目录用例**
     （F5 验收）。
- **备选（若最终选择保留）**：**必须三件套齐做**——rc 契约（0 精确/2 降级/1 未找到）
  + 写操作（`--cleanup`/`--say`）降级时 fail 且**列出候选目录** + F7 时间戳排序。
  **半保留不可接受**（只做 rc 不修 F7 = 警告之后仍系统性读错对象）。
  删/留方案应记入本文件为**分歧项与备选**，非一致意见。

### F-报告【中】报告 = O(session) 冷路径 × 3 出口 → 约束成文

- **实测（性能视角）**：每 agent 读整个 fork-src jsonl，本次 3 × 789KB = **2.4MB/次**；
  `iter_after_boundary` 逐行扫到边界（本次边界在 777 行中第 772 行 → **99.4% 读取
  用于跳过前缀**）；量化 **50–150ms/次**，×2 出口 ≈ **<0.3s/次分析**。冷路径可接受。
- **处置**：把"报告是 O(session 大小) 的冷路径、**不得进入任何轮询路径**"
  写入既有观测面契约（design.md 契约表"冷路径一次性"行后补半句，**不新开节**）。
- **不做**尾部 seek 优化（为省 <50ms 引入行/字节边界复杂性——复杂度不匹配）。
- 出口应为 3 个（`--report` / `--cleanup` / `--follow` 结束）；`--view --since`
  不附报告（进 LLM context，无用且占 token）——符合职责归属。

### F3【低】`result_path` 不在常量家

- `human_viewer.py:49-56` 定义 `f"{base}-result.md"`；S1 已把 "文件叫什么/多大算
  有效" 收进 `meeting_fs`（`RESULT_MD` / `RESULT_MD_MIN_BYTES`），但拼路径留在
  viewer → 组合层（`start_discussion.py:610`）为拼字符串 import 展示模块。
- 处置：移 `meeting_fs`（与 `RESULT_MD` 同家），viewer re-export 兼容。

### F4【观察】viewer ↔ observability 环

- `observability → human_viewer` 是既有边（`--wait` 用 incremental/is_finished）；
  `human_viewer → observability`（`_print_report` 延迟 import）是**本次新增的反向边**。
- 处置：**不 callback 化**（2 行延迟 import 换接口变化 + 两处调用方改动 = 净增）；
  保持现状 + **不再往环上加第三条边**。`observability.py:156` 函数内重复
  `import human_viewer`（顶层已有）为纯清理项，可延后。

### F8【低】流程段口径行

- "消息 N（含流程信号）" = 消息文件数（含 freezing/pass/concluded + human），
  与配额段（仅 `mode=meeting` 且 `type=message`）并列时同一 agent 两个数字。
- 处置：末尾口径行补半句"消息数含流程信号；配额只计 meeting 发言"。

## 三、经检查确认符合设计（不构成问题）

1. **流程段弃用 commit subject 正则、改消息文件计数**（`observability.py:241`）：
   去掉自由文本耦合（格式一改就静默归零），并与配额/冻结/RR 共用同一次
   `each_agent_messages` 读取——一次读取派生四段，本轮最大的简化净收益。
2. **extension 删除 TS 版重复发现实现**，改调 python 同一入口——单一实现方向正确
   （问题只在信号通道，不在归并本身）。
3. **`_print_report` 延迟 import + fail-open 宽捕获**：两行成本消化模块环，
   保住"报告异常不阻断观看退出"契约；延迟 import 的用法正确（冷路径一次）。
4. **`--status` 在 done 时打印 `[result]` 路径**：目录可省略后调用方无法自己拼路径，
   由机制给出的机器通道——符合单一来源收口方向。
5. **`--say` 按参数个数区分双形态**（不按值猜语义）——与既有约定一致，保持。
6. **`find_current_dir` 同 sid 匹配**：目录名尾缀 `YYYYMMDD-HHMMSS` 可比；
   `repo.git` 判据与 engine 一致（"bare 是讨论存在的唯一标志"）；发现逻辑下沉
   python、wrapper/extension 不各写一份——符合单一事实源。
7. **报告附 `--follow`（用户通道）而非 `--view --since`（主 pi 通道）**：职责归属正确。
