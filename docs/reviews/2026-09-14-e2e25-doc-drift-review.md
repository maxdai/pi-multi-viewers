## 0. 结论摘要

1. **文档漂移的根源不是"文档不够多"，而是"对实现的复述"**——同一事实被多处抄写，
   抄本必随实现演进漂移（本场找到：行为描述 3 处副本、状态列举 3 版不一、版本状态 2 处、
   数字/容量多处）。治本方向 = **现状描述引事实源，不复制**。
2. **最重的一条是唯一一类"行为语义与实现相反"**：README / AGENTS / design.md 三处都
   仍写着"目录发现找不到时**兜底 `mv-*` 并警告**"，而代码是**无兜底、未匹配即报错**
   （读者会等一个永不到来的警告/误以为写入已降级）。
3. **三条治理规则**（本场共识，见 §二）落地后，同类漂移结构性减少。
4. 全部问题分三档：**#1 现状描述校准批** → **#2 E1（错误结论限定）** →
   **#3 治理与小修**（见 §一）。三项"不做"与两项"待核"见 §五/§六。

## 二、治理规则（本场共识，供后续文档维护）

1. **单一事实源**：文档不做第二事实源。**有唯一事实源 → 一律引用**（版本号 →
   `package.json`；选项 → `--help`；报告字段 → `design.md §观测面契约`；状态 →
   `check_status` 定义处；容量 → `design.md §二`）——**与 churn 无关**；
   **无事实源 → 补一行 + 增删同步**（成本按变更频率分级，如 `scripts/` 清单）。
2. **三类改法优先级**（复述类问题）：**删复述引权威 > 最短准确陈述**（无权威入口的
   行为描述）**> 就地改准确**（必须保留语境时）。
3. **两条判据**：① **重复"计算"在冷路径可接受；重复"事实"在文档不可接受**
   （报告两遍遍历不做合并；文档复述必去）。② **数字必须带口径**（测点/样本/是否
   `--force`；"单点数字不宜当承诺"）。

## 五、明确不做（防止把设计当缺陷）

1. **不合并四层文档**（README 用户 / AGENTS 开发 / design 决策 / 方法论测试）——
   职责边界不同；问题不是"文档多"，是"同一事实被复述"。
2. **不删决策记录**（含被否决方案与已失效决策 19 的标记）——记录"当时为什么"是其职责。
3. **不合并 `observability` 两个报告遍历函数**（`_report_session_metrics` /
   `_report_session_levels`）——职责分割 > 遍历次数；报告是冷路径。
4. **不枚举 prompt 主流程命令**——低 churn + 执行自足优先（prompt 的"状态列举"例外：
   已漂移，按 T5 处理）。
5. **不把历史决策段/追溯编号（"审核#N"等）当缺陷**——AGENTS.md 注释引用约定已声明
   不可核验、行为以自描述为准。
