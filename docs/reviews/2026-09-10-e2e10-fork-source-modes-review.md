# 多视角分析结论：审阅 fork 源模式描述与实现是否一致

> 主题：`docs/design.md` + `README.md` + `AGENTS.md` 对 fork 源机制的描述
> 与代码实现（`meeting_fs.py` / `meeting_loop.py` / `start_discussion.py` /
> `scripts/mv.sh`）是否一致。
> 参与者：可读性、性能、铁律（3 视角，各 12–13 条消息，含自由讨论 + RR 轮转）。
> 收敛：全员 pass（无保留异议）；本报告为收敛结论的唯一权威版本。

## 0. 结论摘要

**核心机制描述与实现的一致性：大部分成立，发现 6 组确定不一致 + 3 组登记项。**

- 成立面（双方独立核验）：三模式集合与默认值、budget 语义链（先折叠再裁、
  边界对齐、preface、est 对最终产物重算）、无 compaction 兜底、header 自描述
  字段口径、切换叙事 topic 单一来源、模型拼接无条件化——逐条对得上。
  折叠语义另有**产物侧独立证据**（可读性）：thinking 块 0、省略标记 1071 处、
  header 指纹三 agent 恒同（`est=80106 / dropped=2146`）。
- 不一致面：文档与代码中残留**已废除的模式名**（`curated`/`active`，含用户
  可见 CLI help）；`docs/design.md` §一 的规模数字**混源且无测点**；
  非法 `forkMode` 无 fail-fast（已实测复现静默超窗形态，且磁盘上有持久化
  旧值实例）；wrapper 对 `--fork-mode` **静默忽略**（文档教的操作无效）；
  三处"完整上下文"与有损默认模式**承诺不符**；§三 拆分清单 8 函数 ≠ 实际 11。

**修复清单见 §3（P0/P1/P2 分批）；登记项见 §4；未覆盖见 §5。**

## 2. 一致确认项（描述↔实现核对通过）

1. **模式集合与默认值**：CLI `choices=[compaction,budget,full]`、`default=budget`
   → `gen_protocol` → `meeting_loop` 三处默认 + `proto.get("forkMode") or "budget"`
   → `build_fork_source(mode=)`，全链一致（默认值唯一性另见 §3.3 铁律-3）。
2. **budget 语义链**：compaction 边界起 → 折叠（丢 thinking、工具输出仅最近 8
   条保留全文、参数递归截断**保留结构**）→ 从尾部按**折叠后**规模累计 →
   边界对齐（孤儿 toolResult 向前扩展）→ preface（省略说明 + 压缩摘要）→
   header 对最终产物重算 est。与 design.md §一/§二.1 逐条一致；"先折叠再裁"
   的顺序及反例（80k 预算曾只落到 17.5k）在代码注释与文档一致。
3. **无 compaction 兜底**：`compaction` → 标记 `full`；`budget` → 仍折叠 + 统计。
4. **header 自描述**：`forkSourceMode`（三模式均写）/`forkSourceTokensEst`/
   `forkSourceDropped`（仅 budget）——与 §二.1 口径（"Est 即提醒，不预测请求
   规模"）一致。
5. **切换叙事**：4 条 = 2 对；topic 取 `protocol.json.topic`（meeting_loop 已
   不解析 question.md）。
6. **模型拼接无条件化**（无 `startswith` 形状特判），与决策记录一致。
7. **折叠语义产物侧验证**（可读性独立方法）：源区间 thinking=0、省略标记
   1071 处、三份 header 指纹恒同——与性能的代码侧/构建侧结论双源互证。

## 3. 确定不一致与修复清单（收敛结论）

### 3.1 P0 优先（静默改变行为 / 高风险失真）

#### 铁律-3 与 R1 合并：**模式值必须端到端生效，任一入口不得静默丢弃或静默走偏**

**问题 A（D3，非法/旧 `forkMode` 无 fail-fast，已实测复现）**：

- 推演（铁律）：`build_fork_source` 只对三个字面量判断、无 else 兜底 →
  非法值走"边界后全量、不折叠、无预算上限"的混合分支。
- 实测（性能，`mode="bogus"`）：返回 `(2968, err=None)`、产物 6.13MB、
  0.20s、header `forkSourceMode="bogus"` 且无 est/dropped；对照 compaction
  同源同期 2969 条/6.14MB（差 1 条 = 不补 compaction 条目，与推演逐字吻合）。
- **现实输入**（铁律）：`/tmp/mv-e2e9/disc4/work-*/protocol.json` 持久化着
  rename 前的 `"forkMode": "curated"`——"值只存在于每次生成的 protocol.json，
  无迁移负担"的假设不成立：**值一旦写盘就会存活**。
- 后果链（性能 + 铁律）：静默命中已知最贵形态（≈930k tokens，上午实测被
  provider 400）→ 每轮"发超窗请求 + 失败判定"分钟级 churn；**且**
  `meeting_engine.py:773-779` 统一异常边界把 fs 层报错吞成"每 2s 廉价重试"
  → 600s 后以 `reason="stall"` 收尾（原因错配，误导未来读者）。
- 定性（铁律）：不是"加固"，是**既定 fail-fast 约定的第四层缺口**——三层
  守"源不存在"，这层守"源存在但形状错"。

**问题 B（R1，wrapper 静默丢弃参数）**：`README.md:51-52` 教用户
`mv.sh --start <spec> --fork-mode X`，而 `scripts/mv.sh:295-298` 的 `--start)`
只取 `$2` 后 `exit`，多余参数**静默丢弃**（python 收不到，一直用默认值）。

**修法（一次完成，四层同源）**：

| 层 | 动作 | 理由（分类，写入注释） |
|---|---|---|
| wrapper | `--start` 分支 **哑转发**余参给 python；**不解析值、不注入默认值**；usage 正文/头注释补 `[--fork-mode X]` | 转发者只转发（值识别不在此）；默认值唯一家 = `DEFAULT_FORK_MODE` |
| CLI | `choices` 引用 `FORK_MODES` 常量（早失败） | 人输入早期反馈 |
| loop `__main__` | 新增门（照 `meeting_loop.py:517-522` forkSource 先例）：非法 → `[fatal]` + `sys.exit(1)` | 配置错误不是运行期故障，不进 engine 重试路径 |
| fs | `build_fork_source` 入口（`open` 之前）值域校验 | 值集合定义权在实现处（库调用者守卫） |

**同批引入（配套）**：

- **值集合与默认值单一源**：`meeting_fs.FORK_MODES` / `DEFAULT_FORK_MODE`。
  默认值字面量共 **8 处**（生产 5：`start_discussion.py:915/386/737`、
  `meeting_loop.py:528`、`meeting_fs.py:587`；内部签名 3：
  `meeting_loop.py:265/354/432`）全部替换为常量引用。
- **替换边界（机械判据）**：`DEFAULT_FORK_MODE` **仅**用于默认值位置（8 处）；
  **全部模式名位置保持字面量**——比较 6 处（`meeting_fs.py:622` `!= "full"`、
  632/636/638 `== "compaction"`、641/666 `== "budget"`）+ 赋值 1 处
  （`:640` `mode = "full"`）。机械验收：`grep 'mode [!=]= "'` 恒为 6；
  替换后默认值位置裸 `"budget"` 为 0。改默认值不得改分派（否则该模式分支
  静默走错）。注释落点：常量块一行解释"两种语义角色（缺省填谁 vs 处理哪个
  模式）"+ 641/666 各一行执行提醒；不铺满 6 处。
- **错误措辞对齐既有先例**（`meeting_core.py:130` 枚举合法值）：
  `f"未知 forkMode: {mode!r}（合法值: {FORK_MODES}）"`——对历史值 `curated`
  的报错因此自解释。
- **词表**（design.md §一 表下两行）：合法值 `budget/compaction/full`；
  历史产物/旧 `protocol.json` 可能含 `active`/`curated`（rename 前）→ 按
  非法值处理（D3 证据链与 D1 清扫的共同依据）。
- **死字段收掉**：`read_fork_stats` 的 `"entries": None` 删除（唯一调用方
  只用 mode/est/dropped）；docstring 改为"mode/估算/丢弃数取自 header；
  条数由构建返回值提供"（R4 承诺修正）。
- **验收判据**：fs 门单测（非法 → 返回错误且**目标文件未创建**；错误文本
  含三个合法值）；loop 门走 `tests/test_main_paths.py` 真实 subprocess 装置
  （非法 protocol 值 → 退出码非零 + `[fatal]` 在输出 + **无 fork 源生成
  日志行**）；CLI 早失败行为不变。wrapper 验收：`--fork-mode full` →
  `protocol.json.forkMode == "full"`；不带 → `"budget"`（缺省≠非法，两条路径）。

  （`append_handoff_turns` 只保留尾行：不跨层传状态、不新增失效面）——被
  否决方案集合不完整。修：同层方案**独立成行**（否决表已有先例）或否因
  显式说明"已评估/未采纳（原因）"；量级 0.4s vs ~130s/唤醒（0.3%），
  现在不写代码。

### 3.4 规则与记录形态（收敛结论，非代码改动）

- **规则（可读性提出，铁律归位）：断言强度与范围 ≤ 保证强度与范围**，
  methodology 一条，三维一张表、五例：

  | 维度 | 校核时机 | 例 | 去向 |
  |---|---|---|---|
  | 强度 | 写时 | R2"完整上下文"、R4"取自同一来源"、banner"已启动" | 铁律-5 / 铁律-4 / 登记·乙1 |
  | 范围 | 写时 | "不依赖任何扩展"（构建 vs 整链） | MC 措辞（§3.2） |
  | **引用完整性** | **被引用物状态变化时** | D1.6 假引用；**撤回传播**（引用已撤回断言） | 铁律-1；方法论一句 |

  边界：判据须可指认"位置 + 保证"，不用于文风评审；本体范围 = 制品文本
  （讨论消息不逐句约束——审议过程天然含试探与修正）；讨论记录的失真由
  **引用不豁免**规则拦截（撤回/修正后全部引用处同批更新）。两组自纠样本
  （性能 0006→0008；铁律 0008→0009）作"撤回传播"在讨论面的完整教材。
- **守卫表合一**（可读性提议）：three guards 的三份材料（三态链=效果、
  逐层注释=理由、校验成本=成本）并为**一张表**（列=守卫点/今日状态/本轮
  新增/理由/成本；表后一行"校验开销 <0.01%，不作设计约束"；三态链作效果
  注）。归宿：result.md/design.md 决策记录（权威）+ 代码注释只留指针。
  范围注：三态链只描述 **protocol.json/历史值路径**（CLI 路径今日已
  argparse 早失败，不入表——防"今日什么都不报错"误读）。
- **家的纪律**：制度/清单/词汇的**权威只一处**（design.md 决策记录 或
  methodology），其他位置（代码注释、§三、AGENTS.md）只放**一行指针**；
  完整制度不复制（防"下次改动漏一处"的静默失配）。
- **`--wait` 对 `stopped` 接终态**（铁律提案，可读性加文案要求）：现
  `start_discussion.py:998-1006` 只对 `stalled`/`not-exists` 返回，`stopped`
  落入 10s 轮询无上界（与"loop 死后观察者不收敛"同族）。提案：接终态
  （不新增状态，复用 `check_status` 既有定义），文案点名"未启动/启动后
  崩溃"两种成因与下一步。代价已声明：`--start` 之前调用 `--wait` 会立即
  退出（取舍：无上界等待 vs 提前告知）。

## 5. 方法条目（本轮产出，供 methodology 收录）

1. **分区语义自检**（改名/值域变更的完成判据）：现行描述区旧名必须为空；
   存档/决策记录/git 历史允许保留；清单只在改名提交时刻存在，不建常驻名册。
2. **断言强度/范围 ≤ 保证强度/范围**（制品文本；三维含引用完整性——
   引用不豁免、撤回须传播）。
3. **数字（口径；测点）**：任何引用数字须在同处给出数据源与测点；消费侧
   数字带唤醒序号；配置派生值注推导式；外推标"外推"；事后拟合关系明确
   标注（design.md §二 的"≤20%×（窗口−预留）"即事后归纳，非原始设计目标；
   初版"对齐 MC 88k"是刻度混淆——88k 真实 token ≠ 53k est）。
4. **自反性与混源防范**（本主题特有）：讨论 agent 会读取/引用/回灌讨论
   对象——按文本 marker 划边界必须用**精确等值 + 结构位置**（可读性实例：
   "最后一次出现"定位把 agent 读自己产物的 toolResult 当边界，险些误报
   "折叠失效"）；统计核验先声明数据源与测点、再声明区分手段（三例同源：
   假阳性、持久化旧值、混源表格）。
5. **家的纪律**：制度/清单/词汇权威一处，其余位置一行指针。
