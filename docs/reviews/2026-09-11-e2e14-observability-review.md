# 如何更好的监控整个 discussion 过程的有效性和可监控性？目前的日志系统是否合理？

- 分析日期：2026-09-11
- 参与者：性能 / 简单 / 铁律（3 视角，三轮 me + RR 收束）
- 任务性质：**审阅 + 改进建议，不修改代码**；全部建议未经实施与测试

---

## 0. 结论摘要

**"日志系统是否合理"的直答**：

- 作为**人类排错工具**：**合理**——分层清楚（loop log / wake-logs / status json 各司其职）、单点落盘、成本可忽略（3.4–4.0KB/唤醒）、且是**纯信息层**（全仓无一处解析日志内容参与流程判定）。
- 作为**度量工具**：**不成立**——耗时 / token / 失败重试这几类关键信号要么没有落点，要么只能事后重扫 MB 级数据；一次 44 分钟讨论中**最大的单项浪费（provider 失败重试 ≈11% 墙钟）恰好是最大的观测盲区**（零记录）。

**修正方向**（三方共识）：不是把日志升级为度量接口，而是四件事——

1. **契约显式化**：给每个观测面立一节契约（现在格式/消费者在文档零命中）；
2. **登记两个"无家可归"的字段**（`elapsed_ms` / `rc`，零解析热路径）；
3. **新增唯一只读报告出口 `--report`**（冷路径，读 bare + 登记字段 + session 文档化字段）；
4. **修掉唯一一处"日志兼任判定输入"**（`--wait` 的 `glob(loop-*.log)` 分支，删除）。

## 1. 现状盘点（讨论中核实过的事实）

| 观测面 | 写者 | 格式 | 消费者 | 成本 |
|---|---|---|---|---|
| `loop-<agent>.log` | loop + engine（stdout 重定向） | `[HH:MM:SS] agent: msg` 自由文本 | 人（grep/肉眼） | 2–5 行/唤醒 |
| `wake-logs/<agent>-<epoch>.txt` | loop | CMD + PROMPT 全文（**PROMPT 段与 CMD 内嵌 prompt 逐字重复，占文件 40–43%**） | 人（排错第一手段） | 3.4–4.0KB/唤醒 |
| `status-<agent>.json` | loop | `{"sessionID": ...}` | 流程读取（崩溃恢复） | 一行 |
| `pi-sessions/fork-src-*.jsonl` | pi | 完整 entry（ISO8601 时间戳、`usage`、`stopReason`） | 现状仅 fork 构建 / 会话头解析 | **O(会话总量)，MB 级且随轮次增长** |
| `result.md`（固定位） | resultWriter loop | 结论文档 | 人 | — |
| viewer | —（只读派生） | 状态 + 消息增量 | 人 | 每 2s ≈4 个 git 子进程 + O(全部消息) 解析 |

**关键事实**：

- **日志是纯信息层**：全仓无一处解析日志**内容**做判定（唯 `glob(loop-*.log)` 存在性做过显示分叉——本轮裁定删除，见 §3.4）。
- **契约是隐式的**：四个观测面的格式/消费者在 `design.md` / `README.md` **grep 零命中**——"日志有没有时间戳"需读源码才能回答，这本身就是症状。
- **e2e13 实测（同日本项目的 44 分钟真实讨论）**：框架空闲仅 **3 秒（0.1%）**；**5 次 provider 失败重试 ≈ 11% 墙钟，loop log 零记录**；log 行无日期、无毫秒、无 duration。
- **契约 vs 设计约定**：`design.md` §77"预计值不得用作验收口径：日志中的派生数字只是可读性便利"——约束的是**估算/派生数字不得充当验收口径**，不是"日志不得被消费"（讨论中校正了过宽读法）。

## 3. 共识结论：该做什么（最小集）

### 3.1 观测面契约节入 `design.md`（第一批，零代码）

每面登记：**owner / 格式 / 消费者 / 是否参与判定 / fail-open 性质 / 缺省语义 / 取数成本档 / 人类专用面**。配套写死三条**不变量与纪律**：

- **日志零判定输入（绝对）**；唯一机器内容消费 = `--report` 读取登记字段（fail-open）。
- **缺席 ≠ 0**：观测拿不到的显示 `n/a`，绝不允许把"没测到"写成 0。
- **一个数字一个口径**：跨度/口径必须标名（wake 跨度 ≠ per-response 跨度 ≠ 墙钟）。

取数成本档（未来提案的准入闸门）：

| 档 | 面 | 规则 |
|---|---|---|
| O(1) 捕获 | 数据已在手处（唤醒返回的进程返回值） | 鼓励；只落已登记字段 |
| O(小) 冷路径 | `--report`、`read_protocol` | 允许：按需一次 |
| O(MB) 全量解析 | `pi-sessions/*.jsonl` | **禁轮询/常驻**；仅冷路径按需 |

### 3.2 登记两个字段（第一批，零解析）

现有唤醒/完成行追加：

- **`elapsed_ms=<int>`**：monotonic 差值；**跨度 = pi 进程生命周期（spawn → exit）**；
- **`rc=<int>`**：**总是写**（零成本、权威）；超时/被 kill 时不可得 → 省略（缺席 ≠ 0）；
- 行尾追加；新字段增长过同一"家有无"闸门；ISO8601 时间戳一并升级（**人类可读性/定位用，非度量基础**）。

理由：这两个量**无家可归**（session 首个 entry 之前是黑箱；rc 只有 Popen 知道）——是"无家的就地捕获"、零解析、零 schema。`rc` 同时修掉 P1 的诊断面（一个字段满足"偏差③诊断"与"失败可见"）。

### 3.3 新增 `--report`（第一批，唯一只读出口）

- **输入**：bare（流程时间线/推进节奏）+ 登记字段（`elapsed_ms`/`rc`，可选输出唤醒失败计数）+ **session 的文档化字段**（`usage` / `stopReason` / `timestamp`；流式预过滤；**单一适配器**）。
- **约束**：冷路径一次性；**不持久化**（视图不占"数字的家"；将来审计需求走显式 opt-in）；fail-open（读不出 → `n/a`）；跨度分标；**不得升级为验收 gate**。
- **可输出的有效性代理**（全部派生/复用，无新增持久化）：轮次与配额消耗、RR `pass` 比例、human 插话次数、stall 触发、**最长无进展间隔**（bare commit 间隔）、per-agent 耗时/失败/token。

### 3.4 删 `glob(loop-*.log)` 分支 + 修正 `--wait` 提示文案（第一批）

- 推演确认：现状两个分支的提示**都有可执行性问题**——`--start` 对已存在目录报"请先 --cleanup"（start_discussion.py:1167）；wrapper `--start <base>` 因缺 question.md 失败；真正可执行的是 `--skip-setup --start`（环境不完整则 `--cleanup` 重建）。
- 合并文案（动作完整）：`[wait] 未在运行且未收尾（无 loop 存活、无 result.md）——查 loop-*.log / status-*.json 判断原因；重跑：--skip-setup --start（protocol 缺失则先 --cleanup 后重建）`。
- 连带：`tests/test_main_paths.py` 两例随改。不变量随之成为**绝对式**（无例外条款）。

### 3.5 其余（第一批，小改）

- **wake-log 去 PROMPT 双写**（理由 = 单一来源，**不是**性能）；顺手把 CMD 按 argv 逐元素 `shlex.quote` 成单行（wake-log 才可真行级 grep）。
- **`log()` 合并为单实现**，落 **`meeting_fs`**（IO owner；两模块已 import；与"engine IO 收归 fs"同向；调用点零改动）。契约句：**"文件由 loop 重定向拥有；loop 与 engine 各自产生自己的事件；格式只有一个实现"**。
- **"收尾完成"判据单源** = `concluded` **且** result.md 有效；合成函数落 `human_viewer`（唯一增量实现的持有者），复用同一次 bare 读取——同时修掉 P5。

### 3.6 第二批（不与本轮捆绑）

- **三样观测面**（冻结集合与顺序 / 配额进度 / RR 位置）判定**下沉为公开单一实现**（`_meeting_speak_count` 私有、quota 计算内联在 engine 循环内），出口 = `--report` 现场算；viewer 展示后置；
- 约束：**单次读取**（复用 viewer 已有的那次消息读取，不得新增 git 子进程）；viewer 与 `--report` **共用一个实现**；
- viewer HEAD 短路**重估时点**随第二批（那时刷新成本上升，收益同步上升，同一笔账）。

## 4. 明确不做（及理由）

| 不做项 | 理由 |
|---|---|
| `tok`/`err` 捕获进日志 | **有家**（session 文档化字段）→ 复用，不复制 |
| 第二持久化面（如 `events-<agent>.jsonl`） | 信息不减就不新增数据面 |
| 心跳文件 / 独立常驻监控进程 | 可从 `/proc` + HEAD 派生；第二事实源 → 双写/残留/一致性成本 |
| 轮询/常驻路径消费 MB 面 | 成本随轮次线性放大（`json.loads` 实测占 fork 构建 49%） |
| 运行期 LLM 评分（有效性裁判） | 不确定判定入流程，与"确定性归 loop"冲突；有效性判断留给人 + result.md |
| 目录内 retention / 轮转 | cleanup 是唯一清理点；目录内再加保留策略 = 新增机制 |
| message frontmatter 加时间戳 | 第二事实源 + **该字段由 LLM 写**（不可信）；权威时间 = commit 时间 |
| 日志 JSON 化 / 引入日志库 | 主消费者是人（grep + 肉眼）；机器可读用登记字段 |
| viewer HEAD 短路 | **暂缓**（收益 <1% vs 新分支 + 一条会随未来状态失效的前提；重估时点见 §3.6） |
| 报告自动落固定位 | 视图不占家；留存需求 → 显式 opt-in |

## 5. 核心判据与纪律（本轮的智识产出）

### 5.1 取数判据"**家有无**"（三分支，替代整体二分）

> ① **家有无**：该量是否**已有一个结构化的家**？
> - **无家** → **登记**，给它造家（`elapsed_ms`、`rc`）；
> - **有家且读它不需要越界假设**（文档化字段）→ **复用**（`tok`/`err`；冻结/配额/RR 从 bare 派生）；
> - **有家但只能靠未文档化的私有细节读出** → 按**无家**处理（登记）。
>
> ② **非判定性**：零参与流程判定。
> ③ **可降级性**：删掉产物后行为/判定/复现不变；观察读点允许，但必须 fail-open。
> ④ **成本**：捕获在数据已在手处；产物入既有行或 KB 级；禁入轮询。

### 5.2 三域 owner（事实源边界）

| 域 | 事实 | 性质 | 取数 |
|---|---|---|---|
| bare（git） | 消息 / frontmatter / 协议 | **判定域** | 现场派生 |
| loop log | 进程事实（唤醒/退出/超时/rc） | 无家 | **捕获**（零解析） |
| pi session | LLM 运行事实（usage / stopReason / 耗时） | 有家（文档化） | **冷路径读**（单一适配器） |

### 5.3 数字三类（接 `design.md`《数字的归宿》）

- **A 预估/推算值** → 只作可读性便利，**不得作验收口径**（§77 原文不变）；
- **B 捕获一手实测** → 落既有事件行（唯一落点）；
- **C 可重算派生** → **不落盘**，`--report` 现场算。

### 5.4 人类专用面显式登记

stall/超时等 loop 侧事件标签只在日志里可读，**不假装可派生**；将来若确有"无家且需要"的量，按"家有无"闸门加**一个**字段——**留门，不预建**。

## 6. 分歧与收敛记录（供审阅）

- **A/B 之争（捕获式 vs 派生式）反复四轮**，最终形态是**按字段"家有无"分流**（不是整体二分）。反复的根因是**前提未核实**：§77 读法、session 格式是否文档化、`tok`/`err` 可否恢复——前提逐条核实后收敛。
- **前提钉死（无新证据不再重开）**：① §77 管估算值、不管一手登记与消费；② `tok`/`err` 在 session 有家（官方文档化 schema，实测 27ms/3MB）；③ `elapsed`/`rc` 无家（loop 唯一见证）；④ 冷路径读文档化平台格式是允许的（依赖类别已存在：fork 构建本就解析 session）。
- **记录纠正（三方各自的自我更正）**：铁律修正 §77 过宽读法；简单撤回"知识依赖/脆弱处"论证（未经核实假设）；性能 0011 的三字段接受系消息交叉、依据消失后不坚持；铁律纠正简单 0011 §四.4"报告零 session 依赖"的内部矛盾（三字段条件误抄），简单认领。
- **过程教训**：整体二分命名（捕获式/派生式）两轮同名不同义——收束稿不采用整体形态名，直接写"按 owner 域取数"。
