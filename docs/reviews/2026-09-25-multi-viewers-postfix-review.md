## 2. 本场新发现（按类别）

### 2.1 漏 A：`--reuse` 的错误成功信号 → 修法 ②′（最重要）

- **机制**：`last_ok()` 只扫全日志任意一行 `^OK`（`run_tests.sh:50`），harness 输出**追加**在
  python `OK` 之后 → harness 失败时 `last_ok` 仍真；指纹无条件写（`:90`）→ 下次 `--reuse`
  命中（`:56-57`）并 **exit 0** 而缓存日志含 harness 失败。
- **原方案②的残余洞（铁律 0004 复现）**：仅"失败不写指纹"时，**同源码环境性失败**
  （`MV_REQUIRE_BUN=1` 缺 bun / 中断 / harness 并发）会残留上一轮旧绿指纹 → 仍命中 exit 0。
  已用**逐字复刻的门逻辑**在 /tmp 复现（`→ REUSE 命中：exit 0（而 LAST_LOG 含 harness 失败）`）。
- **②′**：真跑前 `rm -f "$FP_FILE"`；结束 `rc -eq 0` 才写回。`last_ok` 可留但**不能当 ② 的
  替代**（它挡不住本反例）；②′ 后其定位退为"遗留指纹/篡改面"。
- **红绿核验（3 条命令，同参数隔离源指纹）**：① module 全绿 → FP 存在；②
  `env PATH=/usr/bin:/bin MV_REQUIRE_BUN=1` 同参数跑 → rc=1 **且 FP 不存在**；③ `--reuse`
  → 必须"未命中→真跑"（现状会命中 exit 0）。
- **三方裁决**：效率/0012、简单/0012 均认账采纳（补洞 + 单一 rc 判据 + 覆盖中断）。

### 2.2 漏 B：P4 加载期失败分支无覆盖 → 内联（可裁）

- `findPackageRoot` 未导出（`shared.ts:29`），harness 内 import 成功即无法触发；子进程负例
  需**复制** `shared.ts` → 违反「测试对象 = 生产对象」（副本漂移）。
- **裁定**：导出该函数直调、**只断言 throw**（至多含稳定标识 `pi-multi-viewers`）、不锁散文；
  **残差明账**（锁函数、不锁加载期接线；坏掉症状=三命令消失，响亮）。
- **内联本批**（不做事后追加：验证是批次级成本，事后追加=第二次验证循环）；优先级低，若砍
  则记账留与下次改动同批（效率/0007 自我更正）。

### 2.3 设计符合度偏差（D1/D2/D3）

  三命令"）；`git show dfe71cc` 证实该行未动——"改了实现忘改抄本"的漂移。简单认领，改一行。
- **D2**:启动通知「已预填进输入框，按 Enter 执行」在 **pi-web 为不实断言**
  （决策 22:577-581 已写明 `setEditorText` 仅 TUI；复核 `pi-web/static/app.js:1907`、
  `ui-context.ts:456` 空实现）——与 0.8.0 首用事故（预填被忽略）同源。
  **修法：中性单串**（如「复制执行；TUI 下已预填」），**不引 `ctx.mode` 分支**（无 mock/断言
  增量，断言体零改动，仅标签措辞随统一改名处理）；`setEditorText` 调用保留（TUI 增强）。
- **D3**:决策 22:570 对 `stalled` 的复述（"无存活 loop 的静止态"）宽于单一事实源
  （`observability.check_status`：**有 result.md**、无 concluded、loop 均不存活）——按字面
  把 `stopped` 也涵盖。**扩展文案不改**（正常路径恒真），**决策 22 引用化**。

    `preserve_result_md` 读 `HEAD:result.md`（`meeting_fs.py:1238`）→ 侧分支/删除场景可达性低；

  行）——"方括号=机器契约"被稀释。修法：**去方括号**（非新增 `[spec]` 前缀）；已核
  `test_mv_cli.py:312` 只断子串、零测试连锁。
- **B2**:`index.ts:67/72/86/129/198` 五处出路提示引用裸 `mv.sh`，而 `which mv.sh` 为空、
  README:55 教的是安装绝对路径 → 出路不可执行。修法：`shared.ts` 增**常量**

### 2.5 harness 覆盖漏与装置缺口

**漏场景（7 类，均为现存分支）**：① MV `!specDir`（rc=0 无 `[prepare] spec=`）② MV
`!watch` ③ FIN 状态读取失败整支 ④ FIN cleanup 失败 ⑤ SAY find-dir 成功 + sayer 失败
⑥ SAY 空输出（"插话已发送"）⑦ `[start] dir=` 缺失（按 §3-S2 定案 (b) 写作"→ 报错"）。
补方式按"追加用例"（两处必然例外：S2 改成功夹具、sid 装置改 calls 输出格式）；断言名带
分支标识（替代另立清单表——清单=第二抄本必漂移）；现有断言一并统一改名（纯改名零行为）。

**装置缺口（本场新增两项）**：
- **sid 传递零断言**：假 python3 只记 argv（`harness:25-31`）；sid 是 `mv-<sid>-*` 命名与
  find-dir 的唯一钥匙，漏注入 = say/finish **静默定位失败**而 28 条全绿 → 假装置多记
  `$PI_SESSION_ID` + 各命令断言（**升为防静默同级**）。
- **`HERE = new URL(…).pathname`**（`harness:18`）不还原 percent-encoding——实测把
  `extensions/` 与 harness 复制到 `/tmp/space test/repo` 运行即报
  `Cannot find module '/tmp/space%20test/repo/…'`；改 `fileURLToPath`（与生产 `shared.ts`
  同处理）。
