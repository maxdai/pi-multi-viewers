## 一、事实基础（讨论中实测 / 源码核实的依据）

### 1.1 F1：边界子串误判（铁律 0001/#1，性能 0008 独立复核）

**机制**：`meeting_fs.py:327` 的 `iter_after_boundary` 用 `if BOUNDARY_TYPE in line:`（子串包含）判断边界；`BOUNDARY_TYPE = "mv.analysis-start"`（`meeting_fs.py:1264`）。主 session 历史里任何含该字面量的一行（本仓**必然有**——历史里写过引用它的测试 fixture）都会被当成边界 → **其后的全部历史被计入"本轮"**。

**实测**（对三个 `fork-src-*.jsonl` 的快照；"精确边界"= 解析 JSON 后按 `type=custom_message & customType=BOUNDARY_TYPE` 判定）：

| 来源 | 子串起点 / 精确边界 | assistant 条目（子串起 → 精确起） |
|---|---|---|
| 铁律 13:52 快照（响应/sec） | 167 行 / 657 行 | 性能 276→**33**（37.0→**6.1 分**）；简单 303→**60**（40.0→**9.1 分**）；铁律 309→**66**（42.8→**11.9 分**） |
| 性能 0008 独立复核 | 168 行 / 658 行 | 304→**60**；307→**63**；275→**31** |

- 子串首命中 = 一条历史 assistant `toolCall`（`2026-09-12T12:09:42Z`，内容为"写含该字面量的测试 fixture"）；误判起点比真实边界**早约 490 行**。
- 影响面：`observability.py:489`（`_report_session_metrics`：`usage` 四组 + `stopReason` 计数/时长）与 `:559`（`_report_session_levels`：档位对照行）——**本场报告一旦生成即失真**（档位行这次未暴露只因被误收的历史里恰好只有 `max` 一档）。

**e2e19「33m09s > 进程 13m09s、> 墙钟 17m19s」之谜的闭合**：边界正确时 `ΣΔ ≤ 本轮墙钟`（数学事实）→ 该异常**只可能来自非本轮条目**；与同机制实测的 37.0 分（性能 agent）量级吻合。**强支持下的推测**（e2e19 的 session 已随 cleanup 删除，无法逐行复核）；性能 0008 据此**撤回**其 0001 的"跨唤醒空闲"归因。

**设计符合度**：写侧登记字段、读侧猜文本——违反同文件自立的原则"**边界是事实，应登记而非猜**"，且使 docstring 承诺的 fail-safe（"未找到边界 → 空迭代，不得退回全文扫描"）永不触发。

### 1.2 Δ 口径 B 的机制事实（铁律 0001/#2；性能 0008 接受并撤回）

- **每次唤醒（含续接）都在进程启动时写 user 条目**：本场 简单 的 session 中 7 个唤醒 user 条目（05:34:42 / 05:39:34 / 05:40:45 / 05:41:26 / 05:43:17 / 05:44:00 / 05:44:30），**每个后面都直接跟 assistant**。
- 于是跨唤醒空闲位于"**上一唤醒末条 → 本唤醒 user 条目**"之间；而 Δ 只在 assistant 条目上、以"紧邻前一条事件"起算——**user 条目把链断在这里，空闲从不进入任何 Δ**。
- 实测首响 Δ 与非首响 Δ **同量级**（铁律：8.59s；性能：首响 7.3/28.6/6.2/10.3/6.7/4.7/4.9s vs 非首响 3.9/3.2/3.6/25.7/6.7/17.2/7.2s，最大 30.2s）——**无分钟级样本**。若 B 排的是空闲，这里应出现分钟级样本。
- 结论：**B 的排除集恒等于"每次唤醒的首条响应"**（进程内真实生成耗时，且常是最贵的一条）；`design.md:113`/docstring 写的"其 Δ 是空闲，不是生成"**与机制不符**。B 丢的是真数据，不是噪声。

### 1.3 `_strip_jsonc` 的执行级矩阵（S1：简单 0001；铁律 0002 补第三例）

| 输入（合法 JSONC） | 旧状态机 | 新 8 行（当前） |
|---|---|---|
| `{"a": 1, /* say "hi" */ "b": 2}` | ✓ 解析成功 | **✗ 解析失败**（块注释未剥离） |
| `{"a": 1, // see "docs"\n"b": 2}` | ✓ 解析成功 | **✗ 解析失败**（`//` 被删、引号内容残留） |
| `{ // it"s "key": "v, }" }` | 值正确 | **✗ 串值 `"v, }"` 被改为 `"v }"`**（注释内**奇数**引号使配对错位，尾逗号正则仍改到真实串值） |

- 前两例是**新引入的功能回归**（旧实现正确）；第三例证明"串值逐字保留"的契约**仍可被打破**。
- 失败走 fail-open：警告 + "其余键不套用"（可见，但 agent 侧配置退化）。
- 现有用例 `tests/test_meeting_fs.py:1024` 的注释不含引号 → **恰好绕开破点**。

## 三、质量背书与"看了但没问题"

- **`test_string_values_not_rewritten`**：本批质量最好的用例（先红后绿已验证）。
- **不引入 JSONC 解析库**：正确（为读一个布尔开关加依赖 = 净复杂度上升）。

## 五、观察登记与记录规范

- **ban AFT 的连带**：若最终选择 ban，作用域配置机制整条（约 150 行 + 测试）随两笔实测开销（**57s 已归因** + **80–190s 未归因**）一起退场；决策归用户。**两笔开销不得合并成一个数字**。

  1. **一个判断只写一个轴**（性能面 / 正确性分轴写——本场两次"合并轴"错误的教训）；
