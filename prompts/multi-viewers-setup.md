# Multi-Viewers Setup（建立视角文件）

这是**建立视角资产**的流程命令，不是分析内容。`viewers/<视角名>.md` 是**长期资产**
（写好长期复用）。本命令**只新建、不修改已有视角**。

## 第 1 步：先看项目，再提**建议**（不落盘）

机械地读项目（`README.md` / `AGENTS.md` / 代码结构）——据此给出 **3–5 个候选视角**，
每个一行：

    1. <名字> —— <一行镜头>（与其它候选怎样互补/对立）

- 这一步**只提议**：不建文件、不改任何东西
- 建几个**由用户决定**（只建 1 个也行）

**然后结束本回合，等用户输入。**

## 第 2 步：等用户决定

用户会告诉你建哪几个（可能只有一个、也可能点名不在候选里的）。**以用户输入为准**；
若某个视角该用什么镜头没说清 → **问一句**，不要替他定。

## 第 3 步：用命令建文件（内容经 stdin 传给命令，不要直接写文件）

先读 `README.md` 的「视角文件写什么」节——那是唯一事实源（三个要点、正误对照、命名规范）。

每个视角调用一次（正文经 stdin；**命名合法性、不覆盖已有、空正文拒绝、写完校验并
回显**都由命令保证，不需要你另外检查）：

```bash
~/.pi/agent/npm/node_modules/pi-multi-viewers/scripts/mv.sh --set-viewer <视角名> <<'EOF'
<视角正文>
EOF
```

命令会回显**写入路径 + 正文全文 + 校验结果**——那就是第 4 步要展示的东西。
若命令报"视角已存在"：告诉用户，停下等他决定（改名，或他明确要求改动）。

## 第 4 步：展示，等审阅

把命令的回显（路径 + 全文 + 校验）给用户看，请他提修改意见或确认：

- 有意见 → **直接编辑该文件**（`viewers/<名字>.md`）→ 跑一次
  `~/.pi/agent/npm/node_modules/pi-multi-viewers/scripts/mv.sh --viewers` 复核 → 再展示（反复直到他确认）
- 确认后一行交接：视角已建好（启动一次分析至少需要 2 个视角），接下来
  `/multi-viewers "<主题>"` 即可
