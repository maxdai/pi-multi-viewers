# Multi-Viewers Setup（建立视角文件）

这是**建立视角资产**的流程命令，不是分析内容。`viewers/<视角名>.md` 是**长期资产**
（写好长期复用）。本命令**只新建、不修改已有视角**。

## 第 1 步：先看项目，再提**建议**（不落盘）

机械地读项目（`README.md` / `AGENTS.md` / 代码结构）——据此给出 **3–5 个候选视角**，
每个一行：

    1. <名字> —— <一行镜头>（与其它候选怎样互补/对立）

- 这一步**只提议**：不建文件、不改任何东西
- 名字：中文、短（≤32 字符）、不含空白与路径分隔符、**不要用 `human`**（保留名）
- 建几个**由用户决定**（只建 1 个也行）

**然后结束本回合，等用户输入。**

## 第 2 步：等用户决定

用户会告诉你建哪几个（可能只有一个、也可能点名不在候选里的）。**以用户输入为准**；
若某个视角该用什么镜头没说清 → **问一句**，不要替他定。

## 第 3 步：按用户输入建文件（只新建）

写之前**先读 `README.md` 的「视角文件写什么」节**（唯一事实源：三个要点 + 正误对照 +
命名规则）。要点：

- 纯内容、无 frontmatter、无标题——**文件名就是全部元数据**
- 必含三条：① **单一 lenses**（所有观点必须从该视角出发）② **不越界**（其它视角由
  别的参与者负责；**不要**列举是哪几个——参与者会变，列举会过期）③ **交锋义务**
  （对其它视角的观点可认同或反驳，但要用本视角的论据）
- **只写视角本身**：身份（"你是 X"）、参与者名单、消息格式、独立参与者纪律都由脚本
  生成，**不要写进文件**

写完跑一次只读检查（会列出视角并用代码判据校验名字与空正文）：

```bash
~/.pi/agent/npm/node_modules/pi-multi-viewers/scripts/mv.sh --viewers
```

**已有同名文件 → 不覆盖**：告诉用户"该视角已存在"，停下等他决定（改名，或他明确
要求改动）。

## 第 4 步：展示，等审阅

把每个新建文件的**路径 + 全文**展示给用户，请他提修改意见或确认：

- 有意见 → 改 → **再展示**（反复直到他确认）
- 确认后一行交接：视角已建好（启动一次分析至少需要 2 个视角），接下来
  `/multi-viewers "<主题>"` 即可
