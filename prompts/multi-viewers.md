# Multi-Viewers（多视角协同分析）

**分析主题：$1**（视角来自项目 `viewers/`，不在命令行指定）

这是用户手动触发的流程命令，不是分析内容。**严格按以下步骤执行**，
完成第 3 步后**结束当前回合**（不等待、不轮询、不转述全文）。

## 视角从哪来

**唯一来源：项目 cwd 下的 `viewers/*.md`**（稳定视角资产——文件名即视角名，
写好长期复用；wrapper 会把它们快照进 spec，可按场微调）。这类资产属于
用户的项目，你**不要**擅自新建或改写它们。

`viewers/` 还没建 → 见步骤 1 的失败分支。**不要**在命令行指定视角。

## 步骤

### 1. 生成 spec

```bash
~/.pi/agent/npm/node_modules/pi-multi-viewers/scripts/mv.sh --prepare "<主题>"
```

**若报错含"未找到 viewers/ 目录"、"仅发现 1 个视角"或"视角任务书不能为空"**：
说明项目缺可用视角。此时**停下来问用户**，不要自己选——建议帮他按
下面的"视角设计原则"写 `viewers/<视角名>.md`（建好后再重跑本步骤）。

### 2. 编辑并请用户审核 spec

编辑 spec 目录：

- `question.md`（第二行起）：**任务类型与产出形态**（审阅→提意见；
  改进建议→说建议；修改→说明可改/需改范围）、分析对象、是否需要达成一致。
  写得越明确，agent 越不会跑偏去做上下文里的其它事（它们的上下文里有
  发起分析的完整对话历史）
- `agents/X.md`（第二行起）：**默认已是 viewers 的快照**——只在用户要求
  按场微调时才改（如"这一场某视角更关注安全"）
- `background.md`（可选）：只写**显式约定的边界**（如"不讨论 API 设计"）。
  **不要**复述对话内容——fork 已让每个 agent 携带主会话上下文
  （默认 budget 模式：按预算裁剪+折叠）
- `models.md`：一般不动（默认继承本机配置）

然后**展示 spec 路径，明确请用户查看/编辑**——用户确认"继续"才执行第 3 步。

## 视角设计原则（建 viewers/*.md 或临时 agents/X.md 时必读）

视角之间**互补或对立都可以**——对立产生的分歧正是多视角分析的价值。
每个视角任务书必须包含：

1. **单一 lenses**：明确该 agent 用什么角度看（性能/简单化/安全/……），
   要求"所有观点必须从该视角出发"
2. **不越界**："其它视角由别的参与者负责，你不要越界展开"（**不要**列举
   具体是哪几个视角——参与者会变，列举会过期）
3. **交锋义务**："对其它视角的观点可以认同或反驳，但要用本视角的论据"

**只写视角本身**：身份（"你是 X"）、参与者名单、消息格式、独立参与者
纪律都由脚本生成（agent 名 = 文件名，单一来源）——任务书里**不要写**，
否则重复且易漂移。

### 3. 启动分析

```bash
~/.pi/agent/npm/node_modules/pi-multi-viewers/scripts/mv.sh --start <spec目录绝对路径>
```

记录 wrapper 输出的**分析目录**，并**原样完整展示**观看命令。

### 4. 结束回合

告知用户：
- 观看：复制上一步的 `!!` 命令执行（实时流式，结束时自动退出并**附本次
  分析报告**——消息数/墙钟/配额/冻结/进程跨度/LLM 用量；用户无需任何
  额外操作即可看到）
- 插话：随时 `/multi-viewers-say <文本>`（自动定位当前分析；也可用 wrapper `--say <目录> "<文本>"`）
- 完成时告诉主 pi，主 pi 会收尾

**然后结束当前回合。**

## 收尾（用户驱动）

```bash
mv.sh --status <分析目录绝对路径>   # done/stopped/running
```

- `done`：读 `<分析目录>-result.md`（与目录同级的固定位）→ 向用户给
  **摘要** → `mv.sh --cleanup <分析目录绝对路径>`
  - cleanup 会再打印一次**分析报告**（删目录前最后一次可读）。报告在
    观看输出末尾已自动出现过，**不必重复转述**——用户问起数字时按需引用
- `stopped`：报告"分析已结束但未生成结果"，不要继续等待
- `running`：告知还在进行，继续等用户通知
